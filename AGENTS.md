# Правила разработки проекта

Этот файл описывает архитектурные стандарты проекта. 
Если пользователь просит создать новый проект или добавить новую функциональность — следуй этим правилам.

## Структура проекта

При создании нового проекта всегда используй следующую структуру папок:

project_root/
├── src/                  # Исходный код
│   ├── api/              # Эндпоинты (FastAPI роутеры)
│   ├── models/           # SQLAlchemy модели (таблицы БД)
│   ├── schemas/          # Pydantic схемы (валидация запросов/ответов)
│   ├── repos/            # Репозитории (работа с БД, CRUD)
│   ├── services/         # Бизнес-логика
│   ├── connectors/       # Внешние интеграции (API, Redis, RabbitMQ)
│   ├── tasks/            # Фоновые задачи (Celery)
│   ├── utils/            # Вспомогательные функции
│   ├── static/images/    # Статика
│   ├── config.py         # Настройки (Pydantic BaseSettings)
│   ├── database.py       # Подключение к БД (session maker)
│   ├── exceptions.py     # Кастомные исключения
│   └── main.py           # Точка входа (создание FastAPI app)
├── tests/                # Тесты (структура повторяет src/)
├── alembic.ini           # Конфиг миграций
├── requirements.txt      # Зависимости
└── Dockerfile

## Правила написания кода (Слои)

1. **API (src/api/)**: Только обработка HTTP-запросов. 
   - Валидация входящих данных через `schemas`.
   - Вызов методов из `services`. 
   - **НИКАКОЙ** логики работы с БД напрямую в API.
2. **Services (src/services/)**: Бизнес-логика.
   - Принимает данные из API, вызывает `repos` для получения/сохранения данных.
   - Выбрасывает кастомные исключения из `exceptions.py`.
3. **Repos (src/repos/)**: Работа с БД.
   - Только CRUD-операции. 
   - Принимает сессию БД (`AsyncSession`) и объекты `models`.
4. **Models (src/models/)**: SQLAlchemy модели. Описывают таблицы.
5. **Schemas (src/schemas/)**: Pydantic модели. Описывают JSON-запросы и ответы.

## Технологический стек по умолчанию

- **Web:** FastAPI, Uvicorn
- **БД:** PostgreSQL, SQLAlchemy (async), Alembic (миграции)
- **Валидация:** Pydantic v2
- **Тесты:** Pytest, httpx (для `AsyncClient`)

## Как действовать, когда просят добавить фичу

1. Прочитай этот файл (`AGENTS.md`).
2. Посмотри структуру через `list_directory("src")`.
3. Если нужно создать новую сущность (например, «Пользователь»):
   - Создай `src/models/user.py` (SQLAlchemy).
   - Создай `src/schemas/user.py` (Pydantic).
   - Создай `src/repos/user.py` (CRUD).
   - Создай `src/services/user.py` (логика).
   - Создай `src/api/user.py` (роутер) и подключи его в `src/main.py`.
4. Проверь работоспособность (запусти или напиши тест).

## Обработка ошибок

- Все ошибки уровня бизнес-логики должны наследоваться от `AppException` в `src/exceptions.py`.
- В API возвращай корректные HTTP-коды (400, 404, 422).

## Использование скиллов (SOP)

В папке `skills/` лежат стандартные операционные процедуры. 
Если задача соответствует названию скилла (отладка, тесты, рефакторинг, новый эндпоинт, работа с БД, инициализация проекта):
1. Прочитай файл скилла (`read_file("skills/<имя>.md")`).
2. Строго следуй его алгоритму.
3. Не изобретай свои паттерны, если скилл уже описывает, как делать.
